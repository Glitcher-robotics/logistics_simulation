# 개발 계획

체크된 항목은 코드·테스트와 일치해야 한다. 다음 단계는 H0의 실제 결과를 확인한 뒤 한 번에 하나의 수직 기능으로 진행한다.

## H0 — 저장소 하네스와 단일 AMR 기준 시나리오

- [x] 로컬 실행, 타입·정적 검사, 포맷, 단위 테스트, 브라우저 테스트, CI 워크플로 구성.
- [x] 3D 창고와 실제 스냅샷을 반영하는 AMR·팔레트.
- [x] 일시정지, 배속, 시간 전진, 초기화, 관점 전환.
- [x] 시나리오 JSON 검증·불러오기·내보내기.
- [x] headless 보고서와 독립 계산한 기준 결과.
- [x] README, 설계, 가정과 검증 절차.

로컬 검증: `pnpm check` 통과(23개 테스트), `pnpm test:e2e` 통과(4개), headless CLI 보고서 생성 확인. 브라우저는 Windows Chrome을 사용했다. GitHub Actions 실행 결과는 원격 워크플로에서 별도로 확인한다.

## M1 — 경로·설비·작업 지점 편집

- [ ] 객체 선택·이동, 속성 패널, 노드/엣지 생성·삭제.
- [ ] 미터 단위 거리 표시와 작업 지점 지정.
- [ ] 저장·불러오기 후 같은 결과를 재현.
- [ ] 잘못된 연결, 설비 관통 경로, 작업 불가능 상태를 표시.

완료 기준: 합성 창고에서 사용자가 경로를 바꾸고, 로봇이 새 경로로 운반하며 변경 전후 이동거리가 계산과 일치한다.

## M2 — 다중 AMR과 공유구간 운영

- [ ] 시나리오를 다중 로봇 스키마로 이행하고 마이그레이션 제공.
- [ ] FIFO/근거리 배정, 도로·교차로 점유, 양보와 대기 원인.
- [ ] 서로 마주보는 로봇, 교차 진입, 장시간 대기, 교착 시나리오.
- [ ] 한 구간에 중복 진입하지 않는 불변식과 충돌/정체 로그.

완료 기준: 같은 교차로에서 두 로봇의 통과 순서와 대기시간을 3D·이벤트 로그·headless 실행에서 동일하게 확인한다.

## M3 — DXF / DWG 레이아웃

- [ ] 합성 DXF 테스트 파일과 최소 LINE/LWPOLYLINE/INSERT 지원 범위.
- [ ] 레이어 선택, 단위 보정, 축 변환, 블록 변환 검증.
- [ ] 도면 바닥 오버레이, 설비·장애물·정차 지점 의미 부여.
- [ ] 변환 누락·외부참조·미지원 객체 보고.
- [ ] DWG 변환 어댑터 결정 및 적용.

완료 기준: 생성한 DXF의 알려진 10 m 구간을 정확히 측정하고, 도면 위에 만든 경로에서 운반을 수행한다.

## M4 — 한 교대 운영 비교와 원인 분석

- [ ] 교대별 작업 유입, 충전·포트 대기, 운영 정책.
- [ ] 작업 생성부터 완료까지의 추적·미완료/기한초과 처리.
- [ ] 같은 시드/작업 목록으로 3대·6대 및 운영안 비교.
- [ ] 시각 탐색과 작업/대기 원인으로 이동하는 재생.
- [ ] 현장 이동·상하차·충전 실측 자료로 보정하는 절차.

완료 기준: 처리량 부족의 원인을 대수·상하차·교통·충전으로 설명하고 관련 시점의 3D 상태로 이동한다.

## 이후 — 무인지게차

조향/후진/회전 영역/팔레트 진입·포크 작업을 별도 모델로 구현한다. AMR의 제자리 회전 모델을 그대로 적용해 공간 적합성을 주장하지 않는다.
