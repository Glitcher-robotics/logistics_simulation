# 검증과 모델 가정

## 환경

Node.js 24 LTS 권장, 최소 22.12.0. 저장소에 지정한 pnpm 버전과 lockfile을 사용한다. 데스크톱 Chrome/Edge 등 WebGL2 지원 브라우저가 필요하다. 생성형 3D 자산이므로 API 키나 별도 그래픽 자산 다운로드가 필요하지 않다.

```sh
pnpm install --frozen-lockfile
pnpm doctor
pnpm check
pnpm exec playwright install chromium
pnpm test:e2e
```

Linux CI는 `pnpm exec playwright install --with-deps chromium`으로 브라우저 OS 의존성도 설치한다. 이미 설치된 브라우저로 검증할 경우 `PLAYWRIGHT_EXECUTABLE_PATH`에 실행 파일 경로를 지정할 수 있다. 환경변수를 지정하지 않으면 Playwright 기본 Chromium을 사용한다.

`pnpm check`는 환경·정적 검사·포맷·타입·단위 테스트·프로덕션 빌드·기준 시나리오를 차례로 검사한다. E2E는 실제 WebGL 캔버스 초기화, 시간 이동/초기화, 운반 완료와 파일 입력 오류를 검사한다. 렌더러 초기화 오류는 화면과 테스트에서 실패해야 한다.

## 단일 AMR 기준값의 독립 계산

`scenarios/single-amr.json`의 첫 공차 이동은 16 m, 각 적재 이동은 26 m이다. 두 번째와 세 번째 작업의 공차 복귀는 각각 26 m이다.

- 총 이동거리: `16 + 26 + 26 + 26 + 26 + 26 = 146 m`.
- 이동시간: `146 / 1.2 = 121.666666… s`.
- 작업시간: `3 × (4 + 3) = 21 s`.
- 마지막 하차 완료: `142.666666… s`.
- 작업 완료 시각: `42`, `92.333333…`, `142.666666… s`.

작업은 0, 20, 60초에 발생하므로 연속 운반 중 추가 유휴시간이 없다. 기준 결과는 `scenarios/expected/single-amr.json`에 고정한다. `pnpm scenario:check`가 이 계산과 엔진 보고서를 허용오차 내에서 비교한다.

## 반드시 보존할 불변식

- 같은 시나리오의 직접 시간 이동과 작은 간격 전진이 같은 상태·이벤트를 만든다.
- 팔레트는 한 위치/소유자에만 존재하며, 하차 완료 전에는 완료 건수를 올리지 않는다.
- 엔진 결과는 프레임률·화면 재생 여부·카메라에 의존하지 않는다.
- 입력 시나리오는 실행 중 변경되지 않는다.
- 잘못된 ID/경로/치수/좌표를 조용히 보정하지 않고 거부한다.

## H0의 해석 한계

단일 AMR, FIFO 배정, 거리 최단경로, 일정 속도, 즉시 방향 전환, 고정 상하차 시간이다. 가감속·충전·여러 로봇의 교통·보행자·정밀 회전·접촉 물리는 포함하지 않는다. 그래픽 랙은 장면 자산이고, 입력 경로의 랙 관통은 기하 검증으로 거부한다. 관제나 SLAM 검증을 수행하지 않는다. 시간·거리 기준값은 이 가정을 검증하며 현장 운반 능력을 보증하지 않는다.

브라우저 캔버스가 그려졌다는 확인만으로 3D 품질을 판단하지 않는다. 기준 창고를 직접 열어 랙, 로봇, 경로, 팔레트의 공간 관계를 확인한다.
