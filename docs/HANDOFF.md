# 현재 상태와 다음 개발

## 구현된 시작점

H0 하네스와 단일 AMR 3D 운반을 구현했다. React/Three.js UI와 순수 TypeScript 사건 엔진을 분리했으며, 시나리오 입력·시간 이동·팔레트 소유권·결과 보고서가 하나의 엔진을 사용한다.

검증 결과:

- `pnpm check`: 통과. 단위·회귀 테스트 23개, 타입·정적 검사·포맷·프로덕션 빌드·기준 시나리오.
- `pnpm test:e2e`: 4개 통과. 실제 WebGL 렌더링, 운반/시간 이동/초기화, JSON 입력 오류/정상 입력, 저장, 이동속도 재계산, 좁은 화면.
- `pnpm scenario:run`: 보고서 생성 확인. 146 m, 3건, 마지막 완료 142.666666667초.
- Windows Chrome으로 3D 창고와 모바일 레이아웃을 시각적으로 확인했다. CI는 Linux + Playwright Chromium으로 같은 명령을 실행하도록 구성했다.

브라우저 검증에서 완료시각을 표시용 소수점으로 반올림하면 마지막 하차 직전에 멈추는 오류를 발견했다. 재생 종료는 내부의 반올림하지 않은 시각을 사용하고, 해당 속도(1.5 m/s)의 회귀 테스트를 추가했다.

생성 결과와 스크린샷은 `artifacts/`에 저장되며 Git에는 포함하지 않는다. CI 실패 시 `test-results/`와 브라우저 보고서를 artifact로 보존한다.

## 바로 다음 작업: M1의 첫 수직 기능

**기존 경로 노드 하나를 3D 화면에서 선택·이동하고 시나리오로 저장한다.**

1. 화면 객체 선택을 도메인 노드 ID에 연결한다.
2. 편집 시 시뮬레이션을 정지하고 편집 가능한 초안과 실행 시나리오를 구분한다.
3. 이동한 좌표가 바닥·랙 간섭 검사를 통과해야 적용한다.
4. 변경된 경로로 AMR이 실제로 운반하고, 이동거리/완료시간이 변해야 한다.
5. 저장한 JSON을 다시 열었을 때 같은 장면과 결과를 재현한다.
6. 경로 길이가 알려진 이동 사례와 잘못된 위치 입력을 단위/E2E로 검증한다.

이 작업 이후 설비 편집과 작업 지점 지정으로 넓힌다. 다중 로봇은 M2에서 자원 점유·교차로·대기 원인을 먼저 구현한다. DWG/DXF는 M3에 별도 입력 어댑터로 추가한다. 단계별 완료 조건은 `PLAN.md`를 따른다.
